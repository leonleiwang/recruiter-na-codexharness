# Recruiter-Na v0.2.1

日期：2026-10-29。发布分支 `release/v0.2.1`，源码 tag `v0.2.1`。本版是开发者预览和个人测试版本，Candidate Decision 继续采用 v5 合同（VERSION=5.0.2）；公开源码版本单独记录为 RELEASE_VERSION=0.2.1。

## 用户可见变化

简历阶段只统计可由简历核验的 JD 能力/经验标签；只能面试确认的标签移出分子与分母，在面试部分保留。三项可核验且全部命中显示 3/3；只确认一项则是 1/3，不将缺少证据项删出分母。

卡片命中仍由现有规则引擎读取简历原文产生，最终资格、候选决策、推荐顺序由 v5 保留。学历/证书/地点单列，报考资格、待考不表示已持证。面试重点采用“提问方向（标签）”，方向来自现有判据描述。

中文 README 作为首页，英文入口为 README.en.md；更新日志保留历史事实边界，补齐工程格式与 Git 忽略配置。

## 验证与限制

专项测试 **154 项通过**，IM 测试 **12 项通过**；源码编译、密钥扫描、diff 空白检查和文档本地链接校验通过。

全量测试 **517 项通过、5 项既有失败、6 项跳过**。相同本地资料下，PR #4 基线为 511 项通过且失败集合相同。五项失败分别为：

- `test_resume_source_pack_is_manifested_but_not_runtime_authority`：缺少私有简历 fixture。
- `test_every_profile_item_exists_as_a_policy_criterion[PROFILE-91603AA55F6E]`：本地画像与 policy 专业知识命名不同。
- 两个画像的 `test_adapted_criteria_equal_the_profile_items_exactly`：本地画像与 policy 条目漂移。
- `test_png_with_txt_suffix_is_not_decoded_as_text`：本地无可用 OCR 引擎。

这些是环境/资料与既有一致性问题，本次没有通过改写 policy 或伪造来源资料消除失败。不能宣称全量测试全绿。

仓库全量测试依赖私有数据基础、adapter 与可用解析/OCR 环境；不能把缺失环境写成业务验收，也不会改 policy 或伪造数据使测试全绿。

历史推荐快照保留原数字，需要重新筛选；已有 JD 确认摘要需重新整理才能更新分组。个人实例仅合成数据，部署后等待用户在自己的机器人验证真实对话。没有生产 MySQL 全库浏览或真实候选人消息发送。
