# 历史简历静态链接处置建议（仅供运维审批，不自动执行）

代码修复只阻止生成新的公开副本。历史 URL 和文件不会自动失效，不能据此宣称历史暴露已解决。

## 默认 dry-run

本轮只生成处置清单，不连接服务器、不删除文件、不改 Web 服务配置。建议经授权的运维人员：

1. 核对旧 `RECRUITER_RESUME_URL_BASE` 对应的**具体静态路由**和旧目录真实路径，限定在
   `/opt/recruiter-na/app/workspace/resume-url`（或经核实的该应用专用目录）。不要扫描原始简历源目录、
   其他应用目录或数据库。遇到符号链接、共享路由或路径不符即停止，另行评估。
2. 默认仅登记文件数量、总字节、时间范围以及路由配置位置；不打开简历内容、不复制文件、不记录 PII、
   下载 URL 或鉴权信息。旧发布器生成的是 32 位十六进制 token 文件名；不符合者不纳入删除候选。
   该命名模式本身并不能证明文件归属，需结合应用发布记录核验。
3. 出具拟撤销的应用专用路由和拟清理目录范围，记录操作者、审批编号、时间和 dry-run 统计。
   没有明确审批不执行变更；本代码没有后台自动清理任务。

## 经单独授权后的处置

- 优先撤销**该应用的公开静态路由**并处理其缓存，阻止旧 bearer URL 继续读取；不要停用共享 Web 服务或
  影响 PulseHR 等其他应用。即使保留文件，撤销公开映射也能阻止该访问路径。
- 使用合成测试文件验证原路由已不可公开访问；不要在报告、终端日志或工单里粘贴真实候选人的 URL。
- 确认数据保留要求后，再对已核实属于该发布器的副本制定逐文件清理清单，另行审批。
  不删除原始简历，不递归清空未知目录，不跟随符号链接，不用通配符删除业务文件。
- 留存批准范围、执行统计、复核结果和剩余缓存/外部副本风险。下载到外部的副本无法由此撤回。

如未来需要 URL 下载，须另立方案实现服务端实际鉴权、owner/request/candidate 绑定、过期、撤销与审计。
给普通静态 URL 加 `expires` 或签名参数不构成访问控制。本轮不实现该服务。
