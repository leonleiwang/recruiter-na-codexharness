# 推荐卡片中的个人简历下载链接（已确认）

## 用户要求

每位候选人的面试重点结束后，空一行显示个人简历下载链接，再空一行显示候选人分隔线。首批三人、换一批及后续所有推荐采用同一格式。

```markdown
④ ……（持续学习）

[下载个人简历](该候选人的受控下载地址)

────────────
```

## 现有能力与限制

现有 SelectedResumeDeliveryService 只在本人需求中选中已推荐候选人后，校验原件根目录并向当前钉钉会话投递文件。现有原件可以复用；没有可直接复用的身份校验下载网址。曾经的无身份静态链接不能重新开放。

## 已确认的范围调整

用户补充确认：成员信息读取权限需审批，改为本企业使用者均可通过有效链接下载。只核验钉钉 OAuth 返回的企业 corpId，不查询成员通讯录、不依赖 qyapi_get_member。该例外仅适用于链接指向的已推荐简历；招聘需求的创建、浏览、继续、删除仍严格 owner-scoped，不提供全库浏览。原 owner 模式作为可选配置保留。

## 建议方案

新增招聘娜专用的 HTTPS 下载入口。卡片中的每个链接绑定需求及候选人，地址不包含姓名、服务器路径、数据库凭据或平台 access token。

打开链接后，钉钉 OAuth 使用 openid corpid；仅接受服务端换码响应中的企业标识与固定企业一致，不查询成员信息。企业标识来自管理员配置或可信 Stream 事件的 chatbotCorpId，并绑定当前应用，不从用户输入或 URL 采信。下载票据绑定签发企业、原需求 owner、已展示候选人与原件指纹；下载时按票据 owner 重查该需求及推荐记录。其他企业、匿名访问、未推荐、已删除的需求、失效链接及越界文件均拒绝。

下载只是查看原件，不改变需求状态、不选择候选、不发起联系。现有“选第几个”流程继续保留。

没有原件或服务不可用时，显示“个人简历暂不可下载，请联系 HR”，不能放虚假链接。真实原件、身份凭据和下载密钥不进入源码或 Release。

## 适用范围

所有推荐回复统一经过同一链接生成/渲染入口，包括首批、换批、继续需求及重试后的推荐。对现有推荐快照在展示时生成链接，不要求重跑耗时筛选，不改变候选顺序、资格结论或标签计数。

## 方案取舍

- 采用企业身份校验的下载入口：按用户补充授权，本企业使用者持有效链接均可下载；需求管理权限不变。需要网站登录回调配置，但不需要成员读取权限。
- 静态原件 URL 或只有随机签名的转发式链接：无法核验点击者是否为本企业登录用户，不采用。
- 继续仅在选中后发送文件：沿用能力最少，但不符合每位候选人末尾提供下载链接的要求。

## 验证与交付

先验证钉钉应用现有身份能力及 HTTPS 回调配置。用回归测试覆盖三位候选各有正确链接、空行/分隔线、换批、跨企业/候选越权（owner 模式另测跨 owner）、已删除需求、失效链接、路径边界和不改变选择状态。测试不将合成数据放入运行候选库。

部署前保留真实 MySQL 数据源和工单备份，仅改招聘娜相关服务。实际验收检查当前三人的原件链接与人员一一对应，并通过桌面实际点击下载。发布版本应与新增下载能力一致，不改写已发布 v0.2.3 的 tag。

用户已确认此设计；实现与部署状态以执行计划和验证记录为准。
